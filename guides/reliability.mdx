---
title: "Retries and errors"
---

Make retries safe, paginate large referral lists, and use the request ID when investigating a failure.

### Retry without creating another invitation

Create and invitation-resend operations require `Idempotency-Key`. After an uncertain response, repeat the same request with the **same key and identical body**. A retry returns the existing result; it does not queue another invitation.

| Situation                       | Result                                 |
| ------------------------------- | -------------------------------------- |
| Same key and same input         | Existing operation result              |
| Same key with different input   | `409 Conflict`                         |
| Conflicting `externalReference` | `409 Conflict`                         |
| Explicit resend with a new key  | A new invitation for the same referral |

Keys are scoped to your partner, environment, and operation. `externalReference` also identifies one referral within that partner and environment. One founder can incorporate more than once using distinct references.

### Read the next page

List responses return `items`, `nextCursor`, and `totalCount`. Pass the returned `nextCursor` as `cursor` until it is `null`. The maximum `limit` is 100. Search results and counts include only referrals you can access.

```bash cURL
curl --get https://api.expedite.now/api/partners/v1/incorporations \
  --header "Authorization: Bearer $EXPEDITE_ACCESS_TOKEN" \
  --data-urlencode 'limit=25' \
  --data-urlencode "cursor=$NEXT_CURSOR"
```

Webhook delivery history uses its returned `next` object as the `before[createdAt]` and `before[id]` query parameters.

### Handle errors

Errors contain `error.code`, `error.message`, and `error.requestId`. Validation errors can also include field-level `issues`. The `X-Request-Id` response header identifies the same request.

| Status | What to do                                          |
| ------ | --------------------------------------------------- |
| `400`  | Correct the input fields                            |
| `401`  | Refresh an expired token or resolve disabled access |
| `403`  | Check the client's required scope                   |
| `404`  | Check the ID and whether your partner may access it |
| `409`  | Resolve the conflicting key or reference            |
| `429`  | Wait at least the `Retry-After` duration            |
| `5xx`  | Retry with backoff and the original idempotency key |

Keep secrets out of URLs, logs, and support messages. Include the request ID when contacting Expedite.
