---
title: "EIN notifications"
---

Subscribe once to incorporation updates. When Expedite verifies an EIN, the same `incorporation.updated` event tells your system to fetch the latest status.

### Receive the update

Verify the webhook signature and deduplicate the event ID. Use `referralId` to identify the referral; there is no separate EIN subscription.

### Fetch the current referral

Use a token with `incorporations:read` to call `GET /incorporations/{referralId}`. Check `progress.ein` and `progress.einIssuedAt`.

```json Verified EIN (response excerpt)
{
	"id": "ref_atlas_labs_001",
	"version": 7,
	"progress": {
		"formation": "INCORPORATED",
		"ein": "ISSUED",
		"einIssuedAt": "2026-11-09T12:00:00.000Z",
		"nextActor": "NONE",
		"nextAction": "Your incorporation is complete"
	}
}
```

This is an excerpt of the referral response. `ISSUED` requires verified EIN evidence. A submitted SS-4 or an unverified uploaded notice does not establish issuance. Neither the status response nor the callback contains the EIN number.

### Update your system

Record the milestone idempotently. The fetched response may be newer than the event; retain the latest version. Progress remains available when the founder declines or withdraws optional document sharing.

### Download the IRS notice, when shared

Use `incorporation_documents:read` to list the referral's documents. An `EIN_NOTICE` appears only when the founder currently grants sharing and the verified notice is available. Request a download link for that document; the link expires after 60 seconds.

### Catch up after downtime

If the EIN was issued before your endpoint became active, fetch the referral to catch up. A later document-sharing grant is not a separate webhook event: query the document list when the founder completes sharing. Keep event-ID deduplication when replaying exhausted deliveries.
