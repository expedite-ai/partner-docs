---
title: "Versioning"
---

The current contract is `/api/partners/v1`. Endpoint schemas are generated from the same oRPC routes and service schemas that validate requests. Internal customer, staff, and MCP procedures are excluded.

### Handle compatible additions

Allow additional response fields and treat new optional fields as compatible changes. Do not infer completion from an unknown state; show the current `nextAction` and retrieve a fresh snapshot.

### Plan for a breaking change

Breaking contract changes require a new API version. Release notes should identify behavior changes before a partner production rollout. Existing clients continue to use their configured version.
